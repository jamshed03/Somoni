The explanations of the type errors (T), shown by `somoni --explain T001`.
A section starts with `## CODE title`; `Wrong:` and `Right:` are followed by an example indented by four spaces.

## T001 unknown type
A type name is used that Somoni does not know: no built-in type and no struct, enum, class or interface of this name
in the file or its imports. Check the spelling, or import the type.

Wrong:

    var p: Pont = Point { x: 1 };
    struct Point { x: int }

Right:

    struct Point { x: int }
    var p: Point = Point { x: 1 };

## T002 unknown variable
A name is read that is no variable here. A variable exists from its line to the end of its block; functions see only
their parameters, their own variables and the `const` of the top level.

Wrong:

    if (true) {
        var inside = 1;
    }
    print(inside);

Right:

    var outside = 0;
    if (true) {
        outside = 1;
    }
    print(outside);

## T003 value of the wrong type
A value is given to a variable, an element or a field whose type is different. Somoni never converts on its own;
convert the value yourself, like `string(n)` or `float(n)`.

Wrong:

    var count: int = "3";

Right:

    var count: int = 3;
    var text: string = string(count);

## T004 name declared twice
A name is declared twice in the same block. An inner block may use the name again, the same block may not.

Wrong:

    var total = 1;
    var total = 2;

Right:

    var total = 1;
    total = 2;

## T005 cannot change a constant
A `const`, or a part of it like a field or an element, gets a new value. Use `var` if it should change.

Wrong:

    const limit = 10;
    limit = 20;

Right:

    var limit = 10;
    limit = 20;

## T006 operator for these types
An operator like `+`, `==` or `&&` gets two values whose types do not fit together, like an int and a bool. Both
sides of `+` have the same type; `&&` and `||` take bools.

Wrong:

    print(1 + true);

Right:

    print(1 + 1);
    print("1" + string(1));

## T007 operator not for this type
An operator is used with a type that does not have it, like `+=` on a bool or `-` on strings.

Wrong:

    var done = true;
    done += true;

Right:

    var done = true;
    done = !done;

## T008 ! needs bool
`!` turns a bool around; other types have no true or false.

Wrong:

    print(!5);

Right:

    print(!(5 > 3));

## T009 - needs a number
A minus in front of a value needs an int or a float.

Wrong:

    print(-true);

Right:

    print(-5);

## T010 condition must be bool
The condition of `if`, `while` or `for` must be a bool. A number or a string is never true or false by itself.

Wrong:

    var count = 3;
    if (count) {
        print("some");
    }

Right:

    var count = 3;
    if (count > 0) {
        print("some");
    }

## T011 break or continue outside a loop
`break` and `continue` only stand inside a `while` or `for` loop.

Wrong:

    print(1);
    break;

Right:

    for (var i = 0; i < 3; i++) {
        if (i == 1) {
            break;
        }
        print(i);
    }

## T012 unknown function
A function is called that does not exist: no own function, no imported one and no built-in one of this name.

Wrong:

    print(sqaure(3));

Right:

    fn square(x: int): int {
        return x * x;
    }
    print(square(3));

## T013 wrong number of arguments
A function or method gets more or fewer arguments than it has parameters.

Wrong:

    fn add(a: int, b: int): int {
        return a + b;
    }
    print(add(1));

Right:

    fn add(a: int, b: int): int {
        return a + b;
    }
    print(add(1, 2));

## T014 argument of the wrong type
An argument has another type than its parameter. Somoni never converts on its own.

Wrong:

    fn twice(n: int): int {
        return n * 2;
    }
    print(twice("4"));

Right:

    fn twice(n: int): int {
        return n * 2;
    }
    print(twice(4));

## T015 function declared twice
Two functions have the same name. Somoni has no overloading by parameter types; give one another name.

Wrong:

    fn show(n: int): void {
        print(n);
    }
    fn show(s: string): void {
        print(s);
    }

Right:

    fn show_int(n: int): void {
        print(n);
    }
    fn show_text(s: string): void {
        print(s);
    }

## T016 name of a built-in function
An own function uses the name of a built-in function like `print` or `len`, which would hide it.

Wrong:

    fn print(n: int): void {
    }

Right:

    fn show(n: int): void {
        print(n);
    }

## T017 return outside a function
`return` only stands inside a function, a method or a lambda.

Wrong:

    print(1);
    return;

Right:

    fn first(): int {
        return 1;
    }
    print(first());

## T018 return of the wrong type
A `return` gives a value of another type than the function returns, or no value where one is needed.

Wrong:

    fn name(): string {
        return 42;
    }

Right:

    fn name(): string {
        return "Ali";
    }

## T019 not every path returns
A function with a result type can end without `return` on some path, for example when an `if` has no `else`.

Wrong:

    fn sign(n: int): string {
        if (n < 0) {
            return "minus";
        }
    }

Right:

    fn sign(n: int): string {
        if (n < 0) {
            return "minus";
        }
        return "plus";
    }

## T020 list elements of different types
All elements of a list have the same type.

Wrong:

    var mixed = [1, "two"];

Right:

    var numbers = [1, 2];
    var texts = ["1", "two"];

## T021 list index must be int
A list is read at a place that is no int.

Wrong:

    var list = [10, 20];
    print(list["0"]);

Right:

    var list = [10, 20];
    print(list[0]);

## T022 no [] on this type
`[]` reads lists and maps, and not other values like an int.

Wrong:

    var n = 5;
    print(n[0]);

Right:

    var digits = [5];
    print(digits[0]);

## T023 wrong number of type arguments
A type like `list<int>` or `map<string, int>` gets the wrong number of types in `< >`; `int` and `string` take none.

Wrong:

    var names: list<string, int> = [];

Right:

    var names: list<string> = [];
    var ages: map<string, int> = {};

## T024 type of an empty list unknown
`[]` alone does not say which list it is. Give it a place that knows its type, like a variable with a type.

Wrong:

    var list = [];

Right:

    var list: list<int> = [];

## T025 type name taken
Two types, like a struct and an enum, have the same name.

Wrong:

    struct Color { name: string }
    enum Color { Red, Green }

Right:

    struct Paint { name: string }
    enum Color { Red, Green }

## T026 field declared twice
A struct or class has two fields with the same name.

Wrong:

    struct Point { x: int, x: int }

Right:

    struct Point { x: int, y: int }

## T027 unknown field
A field is read or set that the struct or class does not have. Check the spelling.

Wrong:

    struct Point { x: int, y: int }
    var p = Point { x: 1, y: 2 };
    print(p.z);

Right:

    struct Point { x: int, y: int }
    var p = Point { x: 1, y: 2 };
    print(p.y);

## T028 field missing in a struct value
A struct value must give every field.

Wrong:

    struct Point { x: int, y: int }
    var p = Point { x: 1 };

Right:

    struct Point { x: int, y: int }
    var p = Point { x: 1, y: 0 };

## T029 no fields on this type
`.` reads fields, but the value has none: it is an int, a string, or an interface, which only promises methods.

Wrong:

    interface Shape {
        area(): float;
    }
    class Square implements Shape {
        side: float = 2.0;
        area(): float {
            return this.side * this.side;
        }
    }
    var s: Shape = new Square();
    print(s.side);

Right:

    interface Shape {
        area(): float;
    }
    class Square implements Shape {
        side: float = 2.0;
        area(): float {
            return this.side * this.side;
        }
    }
    var s: Shape = new Square();
    print(s.area());

## T030 type contains itself
A struct or class has a field of its own type without `?`, so every value would need another one inside it, without
end. Make the field optional, like `next: Node?`.

Wrong:

    struct Node {
        value: int,
        next: Node
    }

Right:

    struct Node {
        value: int,
        next: Node?
    }
    var last = Node { value: 1, next: null };
    print(last.value);

## T031 null for a type without ?
`null` only fits a type with `?`, like `int?`.

Wrong:

    var found: int = null;

Right:

    var found: int? = null;

## T032 type of null unknown
`null` alone does not say which type it is. Give it a place that knows the type.

Wrong:

    var found = null;

Right:

    var found: int? = null;

## T033 void cannot be optional
`void` means no value at all, so `void?` has nothing that could be null.

Wrong:

    fn nothing(): void? {
        return;
    }

Right:

    fn nothing(): void {
        return;
    }

## T034 map key of this type
The keys of a map are strings or ints.

Wrong:

    var prices: map<float, string> = {};

Right:

    var prices: map<string, float> = {};

## T035 type of an empty map unknown
`{}` alone does not say which map it is. Give it a place that knows its type.

Wrong:

    var ages = {};

Right:

    var ages: map<string, int> = {};

## T036 map values of different types
All values of a map have the same type, and all keys too.

Wrong:

    var ages = {"Ali": 30, "Bea": "25"};

Right:

    var ages = {"Ali": 30, "Bea": 25};

## T037 map key of the wrong type
A map is read with a key of another type than its keys.

Wrong:

    var ages = {"Ali": 30};
    print(ages[1]);

Right:

    var ages = {"Ali": 30};
    print(ages["Ali"]);

## T038 cannot loop over this
A `for`-each loop runs over a list, a map or a string, not over other values.

Wrong:

    for (n: int in 5) {
        print(n);
    }

Right:

    for (n: int in [1, 2, 3, 4, 5]) {
        print(n);
    }

## T039 loop variable of the wrong type
A variable of a `for`-each loop has another type than what the loop gives: the element of a list, the key and the
value of a map, or one character as string.

Wrong:

    for (name: string, age: string in {"Ali": 30}) {
        print(name);
    }

Right:

    for (name: string, age: int in {"Ali": 30}) {
        print(name);
    }

## T040 unknown variant
An enum is used with a variant it does not have. Check the spelling.

Wrong:

    enum Color { Red, Green }
    var c = Color.Blue;

Right:

    enum Color { Red, Green, Blue }
    var c = Color.Blue;

## T041 match over this type
`match` chooses a branch for an enum, a result, an int or a string. For a bool, use `if`.

Wrong:

    var done = true;
    match (done) {
        _ => {
            print("any");
        }
    }

Right:

    var done = true;
    if (done) {
        print("yes");
    }

## T042 branch of another type
A branch of `match` is a value or variant of another type than the value matched, like an int over an enum.

Wrong:

    enum Color { Red, Green }
    var c = Color.Red;
    match (c) {
        1 => {
            print("one");
        }
        _ => {
            print("other");
        }
    }

Right:

    enum Color { Red, Green }
    var c = Color.Red;
    match (c) {
        Color.Red => {
            print("red");
        }
        _ => {
            print("other");
        }
    }

## T043 branch twice
Two branches of `match` are for the same variant or value; the second would never run.

Wrong:

    enum Color { Red, Green }
    var c = Color.Red;
    match (c) {
        Color.Red => {
            print("red");
        }
        Color.Red => {
            print("again");
        }
        Color.Green => {
            print("green");
        }
    }

Right:

    enum Color { Red, Green }
    var c = Color.Red;
    match (c) {
        Color.Red => {
            print("red");
        }
        Color.Green => {
            print("green");
        }
    }

## T044 _ not last
`_` takes everything else, so it is the last branch; branches after it would never run.

Wrong:

    var n = 1;
    match (n) {
        _ => {
            print("other");
        }
        1 => {
            print("one");
        }
    }

Right:

    var n = 1;
    match (n) {
        1 => {
            print("one");
        }
        _ => {
            print("other");
        }
    }

## T045 _ would never run
Every variant already has its own branch, so `_` would never run. Leave it out; then a new variant is reported where
a branch is missing.

Wrong:

    enum Color { Red, Green }
    var c = Color.Red;
    match (c) {
        Color.Red => {
            print("red");
        }
        Color.Green => {
            print("green");
        }
        _ => {
            print("other");
        }
    }

Right:

    enum Color { Red, Green }
    var c = Color.Red;
    match (c) {
        Color.Red => {
            print("red");
        }
        Color.Green => {
            print("green");
        }
    }

## T046 branch missing
A `match` over an enum or a result needs a branch for every variant, or `_` for the rest.

Wrong:

    enum Color { Red, Green, Blue }
    var c = Color.Red;
    match (c) {
        Color.Red => {
            print("red");
        }
        Color.Green => {
            print("green");
        }
    }

Right:

    enum Color { Red, Green, Blue }
    var c = Color.Red;
    match (c) {
        Color.Red => {
            print("red");
        }
        _ => {
            print("green or blue");
        }
    }

## T047 variant twice
An enum lists the same variant twice.

Wrong:

    enum Color { Red, Green, Red }

Right:

    enum Color { Red, Green }

## T048 enum without variants
An enum needs at least one variant, otherwise no value of it could exist.

Wrong:

    enum Nothing {}

Right:

    enum Answer { Yes, No }

## T049 type of ok(...) or err(...) unknown
`ok(...)` and `err(...)` build a result, but alone they do not say the other type: `ok(5)` could be
`result<int, string>` or `result<int, bool>`. Give them a place that knows the type, like a return type.

Wrong:

    var answer = ok(5);

Right:

    var answer: result<int, string> = ok(5);
    print(answer);

## T050 field gets no value
A field of a class has no start value and the `constructor` does not set it, so a new object would be incomplete.

Wrong:

    class User {
        name: string;
        age: int;
        constructor(name: string) {
            this.name = name;
        }
    }

Right:

    class User {
        name: string;
        age: int = 0;
        constructor(name: string) {
            this.name = name;
        }
    }

## T051 class written like a struct
An object of a class is made with `new` and its constructor, not with `Name { ... }` like a struct.

Wrong:

    class Point {
        x: int = 0;
    }
    var p = Point { x: 1 };

Right:

    class Point {
        x: int = 0;
    }
    var p = new Point();
    p.x = 1;

## T052 struct made with new
A struct value is written as `Name { field: value }`; `new` is only for classes.

Wrong:

    struct Point { x: int }
    var p = new Point();

Right:

    struct Point { x: int }
    var p = Point { x: 1 };

## T053 this outside a class
`this` is the object a method or constructor runs for, so it only exists inside them.

Wrong:

    print(this);

Right:

    class Greeter {
        name: string = "Ali";
        greet(): string {
            return "Hello " + this.name;
        }
    }
    print(new Greeter().greet());

## T054 this before every field has a value
In a constructor, `this` can only be used as a whole (for a method call, a lambda or to give it away) after every
field has a value. Setting fields with `this.x = ...` is fine before.

Wrong:

    class User {
        name: string;
        age: int;
        constructor() {
            this.name = "Ali";
            print(this.describe());
            this.age = 30;
        }
        describe(): string {
            return this.name;
        }
    }

Right:

    class User {
        name: string;
        age: int;
        constructor() {
            this.name = "Ali";
            this.age = 30;
            print(this.describe());
        }
        describe(): string {
            return this.name;
        }
    }

## T055 name already a field or method
A class has two members with the same name, or a subclass declares a field with the name of an inherited one.

Wrong:

    class Counter {
        count: int = 0;
        count(): int {
            return 1;
        }
    }

Right:

    class Counter {
        count: int = 0;
        current(): int {
            return this.count;
        }
    }

## T056 unknown method
The class, interface or built-in type has no method of this name. For an object seen through a parent class or an
interface, only their methods are known; check with `instanceof` first to use the methods of the subclass.

Wrong:

    abstract class Animal {
    }
    class Dog extends Animal {
        bark(): string {
            return "Woof";
        }
    }
    var a: Animal = new Dog();
    print(a.bark());

Right:

    abstract class Animal {
    }
    class Dog extends Animal {
        bark(): string {
            return "Woof";
        }
    }
    var a: Animal = new Dog();
    if (a instanceof Dog) {
        print(a.bark());
    }

## T057 no methods on this type
Methods exist on objects, strings, floats, lists and maps, not on ints, bools or structs. Use a function instead.

Wrong:

    var n = 5;
    print(n.abs());

Right:

    var n = 5;
    print(abs(n));

## T058 private member
A `private` field or method can only be used inside its own class.

Wrong:

    class Account {
        private balance: int = 0;
    }
    var a = new Account();
    print(a.balance);

Right:

    class Account {
        private balance: int = 0;
        current(): int {
            return this.balance;
        }
    }
    var a = new Account();
    print(a.current());

A class that implements an interface must have every method of it.

    class Square implements Shape {
    }

Right:

    interface Shape {
        area(): float;
    }
    class Square implements Shape {
        area(): float {

        }
    }

## T060 interface method with other types
A method that implements an interface must have exactly its parameter types and its return type.

    interface Shape {

Right:

## T061 interface method not public
Everyone who has the interface may call its methods, so the methods that implement it are public.

Wrong:

    interface Shape {
        area(): float;
    }
    class Square implements Shape {
        private area(): float {
            return 4.0;
        }
    }

Right:

    interface Shape {
        area(): float;
    }
    class Square implements Shape {
        area(): float {
            return 4.0;
        }
    }

## T062 implements a class
After `implements` stand interfaces. To take over the fields and methods of a class, use `extends`.

Wrong:

    class Animal {
    }
    class Dog implements Animal {
    }

Right:

    class Animal {
    }
    class Dog extends Animal {
    }

## T063 new for an interface
An interface only promises methods and has no objects of its own. Make an object of a class that implements it.

Wrong:

    interface Shape {
        area(): float;
    }
    var s = new Shape();

Right:

    interface Shape {
        area(): float;
    }
    class Square implements Shape {
        area(): float {
            return 4.0;
        }
    }
    var s: Shape = new Square();

## T064 extends something that is no class
Only a class can be extended, not a struct, an enum or an interface (an interface is implemented).

Wrong:

    struct Point { x: int }
    class Spot extends Point {
    }

Right:

    class Point {
        x: int = 0;
    }
    class Spot extends Point {
    }

## T065 class inherits from itself
Classes extend each other in a circle, so none of them could come first.

Wrong:

    class A extends B {
    }
    class B extends A {
    }

Right:

    class A {
    }
    class B extends A {
    }

## T066 override missing
A subclass has a method with the name of an inherited one, also an abstract one. Write `override` in front to show
that it replaces it on purpose.

Wrong:

    abstract class Animal {
        abstract sound(): string;
    }
    class Dog extends Animal {
        sound(): string {
            return "Woof";
        }
    }

Right:

    abstract class Animal {
        abstract sound(): string;
    }
    class Dog extends Animal {
        override sound(): string {
            return "Woof";
        }
    }

## T067 nothing to override
A method has `override`, but no parent class has a method of this name. Check the spelling, or leave `override` out.

Wrong:

    class Animal {
        sound(): string {
            return "...";
        }
    }
    class Dog extends Animal {
        override sond(): string {
            return "Woof";
        }
    }

Right:

    class Animal {
        sound(): string {
            return "...";
        }
    }
    class Dog extends Animal {
        override sound(): string {
            return "Woof";
        }
    }

## T068 override with other types or visibility
A method that overrides must have the same parameter types, return type and visibility as the inherited one.

Wrong:

    class Animal {
        sound(): string {
            return "...";
        }
    }
    class Dog extends Animal {
        override sound(): int {
            return 1;
        }
    }

Right:

    class Animal {
        sound(): string {
            return "...";
        }
    }
    class Dog extends Animal {
        override sound(): string {
            return "Woof";
        }
    }

## T069 super(...) missing
The constructor of a subclass must start with `super(...)`, which runs the constructor of the parent class first.

Wrong:

    class Animal {
        name: string;
        constructor(name: string) {
            this.name = name;
        }
    }
    class Dog extends Animal {
        constructor() {
            print("new dog");
        }
    }

Right:

    class Animal {
        name: string;
        constructor(name: string) {
            this.name = name;
        }
    }
    class Dog extends Animal {
        constructor() {
            super("Rex");
            print("new dog");
        }
    }

## T070 super(...) in the wrong place
`super(...)` is only the first statement of the constructor of a subclass. To call a method of the parent class,
write `super.name(...)`.

Wrong:

    class Animal {
    }
    class Dog extends Animal {
        bark(): void {
            super();
        }
    }

Right:

    class Animal {
        sound(): string {
            return "...";
        }
    }
    class Dog extends Animal {
        override sound(): string {
            return super.sound() + " Woof";
        }
    }

## T071 super without a parent class
`super` means the parent class, so it only works in a class that extends another one.

Wrong:

    class Animal {
        sound(): string {
            return super.sound();
        }
    }

Right:

    class Animal {
        sound(): string {
            return "...";
        }
    }

## T072 protected member
A `protected` field or method can only be used inside its class and its subclasses.

Wrong:

    class Animal {
        protected species: string = "?";
    }
    var a = new Animal();
    print(a.species);

Right:

    class Animal {
        protected species: string = "?";
        describe(): string {
            return this.species;
        }
    }
    var a = new Animal();
    print(a.describe());

## T073 readonly field changed
A `readonly` field gets its value once: as a start value or in the constructor of its class.

Wrong:

    class Register {
        readonly limit: int = 10;
    }
    var r = new Register();
    r.limit = 20;

Right:

    class Register {
        readonly limit: int;
        constructor(limit: int) {
            this.limit = limit;
        }
    }
    var r = new Register(20);
    print(r.limit);

## T074 Class::name for something that is not static
`Class::name` reaches static methods and fields. Other members belong to an object.

Wrong:

    class User {
        name: string = "Ali";
    }
    print(User::name);

Right:

    class User {
        name: string = "Ali";
    }
    print(new User().name);

## T075 static method called on an object
A static method belongs to the class, not to an object; call it as `Class::name(...)`.

Wrong:

    class Calculator {
        static square(x: int): int {
            return x * x;
        }
    }
    var c = new Calculator();
    print(c.square(2));

Right:

    class Calculator {
        static square(x: int): int {
            return x * x;
        }
    }
    print(Calculator::square(2));

## T076 new for an abstract class
An abstract class has no objects of its own; make an object of a subclass.

Wrong:

    abstract class Shape {
    }
    var s = new Shape();

Right:

    abstract class Shape {
    }
    class Square extends Shape {
    }
    var s: Shape = new Square();

## T077 abstract method not overridden
A class that extends an abstract class must override each of its abstract methods, unless it is abstract itself.

Wrong:

    abstract class Animal {
        abstract sound(): string;
    }
    class Dog extends Animal {
    }

Right:

    abstract class Animal {
        abstract sound(): string;
    }
    class Dog extends Animal {
        override sound(): string {
            return "Woof";
        }
    }

## T078 super for an abstract method
An abstract method has no body, so `super.name()` has nothing to call.

Wrong:

    abstract class Animal {
        abstract sound(): string;
    }
    class Dog extends Animal {
        override sound(): string {
            return super.sound();
        }
    }

Right:

    abstract class Animal {
        abstract sound(): string;
    }
    class Dog extends Animal {
        override sound(): string {
            return "Woof";
        }
    }

## T079 instanceof on no object
`instanceof` asks what class an object has; ints, strings and other values have none.

Wrong:

    class Dog {
    }
    var n = 5;
    print(n instanceof Dog);

Right:

    class Dog {
    }
    var d = new Dog();
    print(d instanceof Dog);

## T080 instanceof that is never true
The value can never be of this class, because the classes are not related; the check would always be false.

Wrong:

    class Animal {
    }
    class Dog extends Animal {
    }
    class Cat extends Animal {
    }
    var d = new Dog();
    print(d instanceof Cat);

Right:

    class Animal {
    }
    class Dog extends Animal {
    }
    class Cat extends Animal {
    }
    var a: Animal = new Dog();
    print(a instanceof Cat);

## T081 instanceof with no class or interface
After `instanceof` stands a class or an interface, not a struct or another type.

Wrong:

    struct Point { x: int }
    class Dog {
    }
    var d = new Dog();
    print(d instanceof Point);

Right:

    class Dog {
    }
    var d = new Dog();
    print(d instanceof Dog);

## T082 static field without a start value
A static field belongs to the class and exists before any object, so it needs a start value.

Wrong:

    class Counter {
        static count: int;
    }

Right:

    class Counter {
        static count: int = 0;
    }

## T083 start value of a static field not fixed
The start value of a static field must be known when the program is written: a number, a string, a list of them and
the like, without calls, `new` or variables.

Wrong:

    class User {
        static first: User? = new User();
    }

Right:

    class User {
        static first: User? = null;
    }

## T084 static field used on an object
A static field belongs to the class; use it as `Class::name`.

Wrong:

    class User {
        static count: int = 0;
    }
    var u = new User();
    print(u.count);

Right:

    class User {
        static count: int = 0;
    }
    print(User::count);

## T085 unknown static field
The class has no static field of this name. Check the spelling.

Wrong:

    class User {
        static count: int = 0;
    }
    print(User::total);

Right:

    class User {
        static count: int = 0;
    }
    print(User::count);

## T086 constant of an imported file not fixed
A `const` in an imported file must be a fixed value, so that it is the same however the file is used.

Wrong:

    import { LIMIT } from "settings.smn";
    print(LIMIT);

File settings.smn:

    export const LIMIT = len([1, 2, 3]);

Right:

    import { LIMIT } from "settings.smn";
    print(LIMIT);

File settings.smn:

    export const LIMIT = 3;

## T087 ? outside a function with a result
`?` gives an `err` back at once, so it only works in a function that returns a `result` itself.

Wrong:

    fn read(): int {
        return int("5")?;
    }

Right:

    fn read(): result<int, string> {
        var n = int("5")?;
        return ok(n);
    }
    print(read());

## T088 ? on no result
`?` takes the value out of an `ok`, so it needs a `result`.

Wrong:

    fn next(n: int): result<int, string> {
        return ok(n? + 1);
    }

Right:

    fn next(n: int): result<int, string> {
        return ok(n + 1);
    }
    print(next(1));

## T089 ? with another error type
`?` passes the `err` on unchanged, so its type must be the error type of the function.

Wrong:

    fn read(): result<int, int> {
        var n = int("5")?;
        return ok(n);
    }

Right:

    fn read(): result<int, string> {
        var n = int("5")?;
        return ok(n);
    }
    print(read());

## T090 built-in function as a value
Only own functions can be stored as values; built-in functions like `print` cannot. Wrap one in a lambda.

Wrong:

    var show: fn(int): void = print;

Right:

    var show: fn(int): void = fn(n) => print(n);
    show(3);

## T091 value is no function
Something is called with `(...)` that is no function, like a field that holds an int.

Wrong:

    struct Point { x: int }
    var p = Point { x: 1 };
    p.x(2);

Right:

    struct Button { action: fn(int): void }
    var b = Button { action: fn(n) => print(n) };
    b.action(2);

## T092 copy in a lambda changed
A lambda copies the outside variables it uses when it is made; it can read the copies but not change them, and it
cannot set fields of `this`. Call a method of the object instead.

Wrong:

    var count = 0;
    var add = fn() {
        count += 1;
    };

Right:

    var count = 0;
    var next = fn() => count + 1;
    count = next();
    print(count);

## T093 super inside a lambda
`super` cannot be used inside a lambda. Call the method of the parent class before and use its result.

Wrong:

    class A {
        m(): int {
            return 1;
        }
    }
    class B extends A {
        override m(): int {
            var f = fn(): int => super.m();
            return f();
        }
    }

Right:

    class A {
        m(): int {
            return 1;
        }
    }
    class B extends A {
        override m(): int {
            var first = super.m();
            var f = fn(): int => first + 1;
            return f();
        }
    }

## T094 tuple with one element
A tuple holds at least two values; for one value, use the value itself.

Wrong:

    var single: (int) = 1;

Right:

    var pair: (int, string) = (1, "one");
    var single: int = 1;

## T095 tuple element out of range
A tuple with two elements has `.0` and `.1`; there is no `.2`.

Wrong:

    var pair = (1, "one");
    print(pair.2);

Right:

    var pair = (1, "one");
    print(pair.1);

## T096 .0 on no tuple
`.0`, `.1` and so on read the elements of a tuple; other values have none.

Wrong:

    var n = 5;
    print(n.0);

Right:

    var pair = (5, 6);
    print(pair.0);

## T097 name of an imported module
`import * as math` makes `math` the name of the module, so no variable, function or type may have it.

Wrong:

    import * as math from "math.smn";
    var math = 1;

File math.smn:

    export fn square(x: int): int {
        return x * x;
    }

Right:

    import * as math from "math.smn";
    var result = math.square(2);
    print(result);

File math.smn:

    export fn square(x: int): int {
        return x * x;
    }

## T098 module used as a value
A module name is no value by itself; use a name in it, like `math.square`.

Wrong:

    import * as math from "math.smn";
    print(math);

File math.smn:

    export fn square(x: int): int {
        return x * x;
    }

Right:

    import * as math from "math.smn";
    print(math.square(3));

File math.smn:

    export fn square(x: int): int {
        return x * x;
    }

## T099 match over values without _
There are endless strings and ints, so a `match` over them needs `_` as the last branch for all other values.

Wrong:

    var answer = "yes";
    match (answer) {
        "yes" => {
            print("good");
        }
    }

Right:

    var answer = "yes";
    match (answer) {
        "yes" => {
            print("good");
        }
        _ => {
            print("something else");
        }
    }

## T100 if (var ...) with a value that is never null
`if (var name = value)` runs only when the value is not null; for a value without `?`, it would always run. Use a
normal `var`.

Wrong:

    if (var price = 2.5) {
        print(price);
    }

Right:

    var price = 2.5;
    print(price);

## T101 void stored in a variable
The call gives no value (its type is `void`), so there is nothing to store.

Wrong:

    var shown = print(1);

Right:

    print(1);

## T102 type of a constant known only later
A `const` of the top level without a type, whose value is computed, has its type only from its own line on. A
function above it that uses it cannot know the type yet. Write the type, or move the constant up.

Wrong:

    fn total(): int {
        return BASE * 2;
    }
    const BASE = len([1, 2]);
    print(total());

Right:

    const BASE = len([1, 2]);
    fn total(): int {
        return BASE * 2;
    }
    print(total());

## T103 type of a lambda parameter unknown
A lambda may leave out the types of its parameters only where a function type is expected, like an argument of
`map` or a variable with a type.

Wrong:

    var next = fn(x) => x + 1;

Right:

    var next = fn(x: int) => x + 1;
    var twice: fn(int): int = fn(x) => x * 2;
    print(next(twice(3)));

## T104 lambda with another number of parameters
The expected function type has another number of parameters than the lambda.

Wrong:

    var f: fn(int): int = fn(x, y) => x;

Right:

    var f: fn(int): int = fn(x) => x;
    print(f(1));

## T105 value that cannot stand in a string
In `"... {value} ..."` and in `{{ }}` of a template stand ints, floats, bools and strings. A list or an object needs
to be turned into text first; a value with `?` needs a null check first.

Wrong:

    var names = ["Ali", "Bea"];
    print("Names: {names}");

Right:

    var names = ["Ali", "Bea"];
    print("Names: {names.join(", ")}");
